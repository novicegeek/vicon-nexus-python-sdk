FAQ

Organized as “symptom → cause → fix”. Most problems come from three places: environment bitness/version, error handling that is too quiet, and historical defects in the utils package.

Connecting and installing

Constructing ViconNexus() raises IOError: Unable to connect to Nexus

Possible causeFix
Nexus is not running / sign-in not finishedOpen Nexus by hand first, get to the main window, then run the script
Connecting to a remote hostCheck that the hostname in ViconNexus('host') resolves and that the firewall lets it through
Version mismatchVerify with GetServerInfo(); the SDK and Nexus major versions must match
Nexus is in live mode or is running a pipelineStop acquisition, wait for the pipeline to finish, then retry

DLL load failed on import / ImportError: cannot import name _NexusClient3

  • Python bitness does not match the .pyd — the SDK ships 64-bit packages only, so a 64-bit interpreter is required.
  • Only the .py files were copied, without _NexusClient3.pyd and the boost_*.dll / ViconSDKClientCPP.dll in the same directory.
  • Install the package with pip install instead of copying individual files by hand — MANIFEST.in bundles the binaries with it.
python -c "import sys; print(sys.maxsize > 2**32)"   # must be True (64-bit)

utils raises module 'numpy' has no attribute 'long'

viconnexusutils uses np.long and np.bool; both aliases were removed in numpy 1.24. 

:: Option 1: pin an older numpy
pip install "numpy<1.24"

:: Option 2: patch the source (two replacements, a global search is enough)
::   np.long  → int
::   np.bool  → bool

Non-ASCII paths / non-ASCII subject names fail

The facade applies encode('utf-8') to every string argument, so non-ASCII is supported in principle. Under Python 2, however, source files are decoded as ASCII by default, so any script containing non-ASCII characters must declare its encoding: 

# -*- coding: utf-8 -*-
from __future__ import unicode_literals

On Python 3 just save the script as UTF-8. If it still fails, rename the item to pure ASCII inside Nexus first, to confirm whether the problem is really encoding.

Python 2 vs Python 3

SymptomCause and fix
Example script raises SyntaxErrorThe official examples use Python 2 syntax (print 'x', xrange, and sys.exit without parentheses). Convert them to print() and range.
String literals of the form b'Colin'The low level expects bytes; if you call vicon.Client.* directly you must encode yourself.
Return values come back as bytesThis only happens when you bypass the facade. The facade decodes everything to str through _get_safe_string_value().
Integer division differencesdeviceRate / rate is floor division in Py2 and true division in Py3. Write // when you need an integer; when you need a float, keep / and cast it with int() before using it in range.

Error handling

The SDK's error model is “quiet”: methods do not raise, they return None or an empty list while printing the reason to stderr. So the key to a robust script is not try/except but read-back verification.

Output you may seeMeaning
Strings such as Subject not foundThe low-level ResultString() was printed directly
Empty list / length 0The read failed or the object does not exist (not “no data” — missing data returns a False list of the same length)
No output, but the data is unchangedThe write failed and the exception was swallowed
 
def write_trajectory_safe(vicon, subject, marker, x, y, z, e):
    vicon.GenerateErrors = False
    try:
        vicon.SetTrajectory(subject, marker, x, y, z, e)
        got = vicon.GetTrajectory(subject, marker)
    finally:
        vicon.GenerateErrors = True

    if len(got[0]) != len(x) or got[1][0] != y[0]:
        raise RuntimeError('write did not take effect: ' + subject + '/' + marker)
Three practices
  1. Before a batch job starts, validate that the targets exist with GetSubjectNames() / GetModelOutputNames().
  2. After writing, read back a sample frame and compare.
  3. Use vicon.GenerateErrors = False to suppress noise, but always pair it with read-back verification — otherwise errors become completely invisible.

Performance

Anti-patternAlternative
Writing a whole trajectory frame by frame with SetTrajectoryAtFrameSetTrajectory in a single call
SetDeviceChannelAtFrame per frameSetDeviceChannel (the source explicitly warns that the former is slower)
Calling GetModelOutputDetails again for every subjectCache it in a dict; one pass is enough
Running large loops in a script inside NexusMove it to an external process and batch with OpenTrial/SaveTrial

Rule of thumb: a single call is in-process IPC, so the cost comes mainly from the number of round trips rather than the data volume. Reading or writing a whole trajectory (thousands of frames × dozens of channels) is usually far faster than a per-frame loop.

I changed the data but the file did not change

Set* modifies only the in-memory trial. Persisting it requires SaveTrial(timeout), and that must be called from an external Python process — calling it from a script inside Nexus fails or hangs. 

vicon.SetModelOutput(subject, 'MyOutput', data, exists)
vicon.SaveTrial(30)          # external process only
# or: defer all saving to the end; from an inside script, ask the user to save in Nexus

Timeouts and pipelines

  • The timeout on OpenTrial / SaveTrial / CloseTrial / RunPipeline is only a client-side wait limit; after it expires the action in the host may still be running.
  • After a timeout, do not send the next command immediately — poll the state first (for example, whether GetTrialName() has changed).
  • While a pipeline is running you cannot open or save a trial, nor start another pipeline.
  • With unsaved data, OpenTrial may pop up a host dialog that blocks automation — call SaveTrial first.

Multithreading / concurrency

The client talks to Nexus over a serial command model. Using one ViconNexus instance from several threads produces mismatched responses; use a single thread plus a queue, or create one connection per thread (not recommended — the host side is still serial).

Suggested fix: for code that goes through these paths, write it yourself with ViconNexus plus numpy instead of routing through utils.

Small traps in the example scripts

  • DetectFootEvents.py: trajExists[idx] indexes a 0-based list with a 1-based frame number, off by one frame; SamplesPerFrame becomes a float under Py3.
  • GapFilling/ProcessGaps.py: E is undefined when the gap length is 0.
  • Most examples never call Disconnect(); if you run repeatedly over a long period, add it yourself.
