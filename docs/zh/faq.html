常见问题

按“症状 → 原因 → 处理”组织。大部分问题来自三处：环境位数/版本、错误处理太安静、utils 包的历史缺陷。

连接与安装

构造 ViconNexus() 抛 IOError: Unable to connect to Nexus

可能原因处理
Nexus 没启动 / 未登录完成先手工打开 Nexus，进到主界面再跑脚本
连的是远程主机确认 ViconNexus('host') 主机名解析、防火墙放行
版本不匹配用 GetServerInfo() 核对；SDK 与 Nexus 大版本需一致
Nexus 正在 live 模式或正在跑 pipeline停止采集、等 pipeline 结束后重试

导入时报 DLL load failed / ImportError: cannot import name _NexusClient3

  • Python 位数与 .pyd 不匹配——SDK 只有 64 位包，必须用 64 位解释器。
  • 只拷贝了 .py，没带 _NexusClient3.pyd 与同目录 boost_*.dll / ViconSDKClientCPP.dll。
  • 用 pip install 装包，而不是手工复制单个文件——MANIFEST.in 会把二进制一起装进去。
python -c "import sys; print(sys.maxsize > 2**32)"   # 必须是 True（64 位）

utils 报 module 'numpy' has no attribute 'long'

viconnexusutils 用到了 np.long 与 np.bool， 这两个别名在 numpy 1.24 被移除。 

:: 方案一：钉旧版 numpy
pip install "numpy<1.24"

:: 方案二：改源码（两处替换，全局搜索即可）
::   np.long  → int
::   np.bool  → bool

中文路径 / 中文受试者名出错

门面层对所有字符串入参做了 encode('utf-8')，理论上支持非 ASCII。 但 Python 2 下源文件默认按 ASCII 解码，脚本里出现中文必须声明编码： 

# -*- coding: utf-8 -*-
from __future__ import unicode_literals

Python 3 下把脚本存为 UTF-8 即可。仍然失败时，先在 Nexus 里改成纯 ASCII 名称验证是不是编码问题。

Python 2 与 Python 3

现象原因与处理
示例脚本 SyntaxError官方示例是 Python 2 语法（print 'x'、xrange、sys.exit 后无括号）。改成函数式 print()、range。
b'Colin' 形式的字符串底层要 bytes；如果你直接调 vicon.Client.*，需自己 encode。
返回值是 bytes只在绕过门面层时出现。门面层用 _get_safe_string_value() 统一解码为 str。
整数除法差异deviceRate / rate 在 Py2 是整除、Py3 是浮点。需要整数请写 //，需要浮点就保持 / 并显式 int() 后用于 range。

错误处理

SDK 的错误模型很“安静”：方法不抛异常，而是返回 None 或空列表， 同时把原因打印到 stderr。因此写健壮脚本的关键不是 try/except， 而是读回校验。

你可能看到的输出含义
Subject not found 之类字符串底层 ResultString() 被直接打印
空列表 / 长度 0读取失败或对象不存在（不是“没有数据”——没有数据会返回等长的 False）
没有输出但数据没变写入失败，异常被吞
 
def write_trajectory_safe(vicon, subject, marker, x, y, z, e):
    vicon.GenerateErrors = False
    try:
        vicon.SetTrajectory(subject, marker, x, y, z, e)
        got = vicon.GetTrajectory(subject, marker)
    finally:
        vicon.GenerateErrors = True

    if len(got[0]) != len(x) or got[1][0] != y[0]:
        raise RuntimeError('写入未生效: ' + subject + '/' + marker)
三条实践
  1. 批量任务开始前用 GetSubjectNames() / GetModelOutputNames() 校验目标存在。
  2. 写入后抽样读回一帧比对。
  3. 用 vicon.GenerateErrors = False 压噪音，但要配合读回校验，否则错误完全不可见。

性能

反模式替代
逐帧 SetTrajectoryAtFrame 写一整条SetTrajectory 一次写完
逐帧 SetDeviceChannelAtFrameSetDeviceChannel（源码明确警告前者更慢）
对每个受试者重复 GetModelOutputDetails缓存到字典，一次遍历即可
在 Nexus 内部脚本里跑大循环挪到外部进程，用 OpenTrial/SaveTrial 批处理

经验值：单次调用是进程内 IPC，开销主要来自往返次数，而不是数据量。 整条读写（几千帧 × 几十通道）通常远快于逐帧循环。

改了数据但文件没变

Set* 只改内存中的试次。落盘需要 SaveTrial(timeout)， 且必须在外部 Python 进程中调用——Nexus 内部脚本调用它会失败或卡住。 

vicon.SetModelOutput(subject, 'MyOutput', data, exists)
vicon.SaveTrial(30)          # 外部进程才行
# 或者：跑到最后统一保存；内部脚本则请用户在 Nexus 里手动保存

timeout 与 pipeline

  • OpenTrial / SaveTrial / CloseTrial / RunPipeline 的 timeout 只是客户端等待上限；超时后宿主里的动作可能仍在进行。
  • 超时后不要立刻发下一条命令，先轮询状态（例如 GetTrialName() 是否已变）。
  • pipeline 运行期间不能打开/保存试次，也不能再启动一个 pipeline。
  • 未保存数据时 OpenTrial 可能弹出宿主对话框阻塞自动化——先 SaveTrial。

多线程 / 并发

客户端与 Nexus 之间是串行命令模型。多线程使用同一个 ViconNexus 实例会出现 响应错位，请用单线程 + 队列，或为每个线程各建一个连接（不推荐，宿主侧仍是串行）。

已知问题与文档勘误

源码 docstring 与实际行为不一致

方法问题
GetSubjectParamDetails返回 5 个值，示例只解包 4 个
GetAnalysisParamDetails返回 3 个值，示例按 4 个解包
CreateAnEvent示例里 context 与 event 顺序写反

viconnexusutils 1.0.0 的缺陷

位置现象
NexusAngles.Read布尔掩码维度不匹配，帧数 > 3 时抛 IndexError
NexusAngles.mean写入不存在的 _position，结果全 NaN
NexusSegment.Scale返回 _orientation 而非 _scale
NexusSegment.mean末尾 pass，返回 None
NexusSegment.__rmul__返回 None（写 seg * traj 会得到 None）
SetPosition/SetOrientation/SetScale帧索引未 -1，与读取方法不一致（0 基 vs 1 基）
Write 补帧frames+1: 切片导致跳过一帧

处理建议：涉及这些路径时直接用 ViconNexus + numpy 自己写，不要绕 utils。

示例脚本的小坑

  • DetectFootEvents.py：trajExists[idx] 用 1 基帧号索引 0 基列表，偏一帧；SamplesPerFrame 在 Py3 下变成 float。
  • GapFilling/ProcessGaps.py：缺口长度为 0 时 E 未定义。
  • 多数示例不调用 Disconnect()，长时间反复运行时建议自己补上。
