示例脚本

SDK 自带 8 个示例，覆盖“把数据读出来看看”到“批量补洞、检测足事件”的常见任务。 它们是理解 API 用法最快的入口，但都是 Python 2 语法，直接拿到 Python 3 里要改 print 与 xrange。

脚本作用需要参数
DisplayTrialInfo.py打印试次概况与设备列表无
DisplaySubjectInfo.py打印受试者的标记点/骨段/关节/参数受试者名
DisplayModelOutputInfo.py按分组列出模型输出及分量量纲受试者名
SimpleMidpoint.py生成两点中点的建模标记点受试者 + 2 标记点 + 输出名
DetectFootEvents.py按力阈值检测足着地/离地并写事件脚本内硬编码
GapFilling/ProcessGaps.py线性插值函数（被其它脚本 import）—
GapFilling/FillGaps.py批量填补小缺口—
NexusConformityTest.py安装验收：测量标定杆点距的均值/标准差无（在 pipeline 中运行）

怎么运行

两种方式，取决于脚本是否调用 OpenTrial / SaveTrial / RunPipeline：

:: 方式 A：外部进程（推荐，能力最全）
python DisplayTrialInfo.py

:: 方式 B：Nexus 内部 —— Pipeline 里加一个 "Run Python Operation"
:: 适合作为处理流程的一环，但不能控制试次开关

示例的 if __name__ == "__main__": 段落直接用 sys.argv 取参， 所以命令行方式要按脚本约定补参数。

DisplayTrialInfo.py

最小的“读一读”示例：试次名、路径、帧数、帧率、可更新区间、受试者列表、设备列表。

(path, name) = vicon.GetTrialName()
framecount = vicon.GetFrameCount()
framerate  = vicon.GetFrameRate()
(startFrame, endFrame) = vicon.GetTrialRange()

for deviceID in vicon.GetDeviceIDs():
    deviceDetails = vicon.GetDeviceDetails(deviceID)
    deviceName, deviceType, deviceRate = deviceDetails[0:3]
    print 'Device', deviceID, deviceName, deviceType, deviceRate

用到了 GetTrialName、 GetFrameCount、 GetTrialRange、 GetDeviceIDs、 GetDeviceDetails。 注意它没有 Disconnect()，作为一次性脚本无妨。

DisplaySubjectInfo.py

受试者画像：标记点清单 → 每个骨骼段关联的标记点 → 关节的父子段 → 静态参数值。

for Segment in vicon.GetSegmentNames(subject):
    markers = vicon.GetSegmentDetails(subject, Segment)[-1]
    print Segment, markers

for Joint in vicon.GetJointNames(subject):
    (parent, child) = vicon.GetJointDetails(subject, Joint)
    print Joint, '[', parent, '-', child, ']'

for param in vicon.GetSubjectParamNames(subject):
    value = vicon.GetSubjectParamDetails(subject, param)[0]
    unit  = vicon.GetSubjectParamDetails(subject, param)[1]

GetSegmentDetails(...)[-1] 取的是第 3 个返回值（markers）。 参数那段连续调用两次 GetSubjectParamDetails，是冗余往返——自己写时合并成一次解包更好。

SimpleMidpoint.py

把两个标记点的中点写成一个新的建模标记点。演示了“创建输出 → 读输入 → 算 → 写回”的完整闭环， 也是最常见的自定义点生成模板。 

vicon.CreateModeledMarker(subject, name)          # 先建容器

(X1, Y1, Z1, E1) = vicon.GetTrajectory(subject, marker1)
(X2, Y2, Z2, E2) = vicon.GetTrajectory(subject, marker2)

(data, exists) = vicon.GetModelOutput(subject, name)
for i in range(vicon.GetFrameCount()):
    if E1[i] and E2[i]:
        exists[i] = True
        data[0][i] = (X1[i] + X2[i]) / 2.0
        data[1][i] = (Y1[i] + Y2[i]) / 2.0
        data[2][i] = (Z1[i] + Z2[i]) / 2.0
    else:
        exists[i] = False

vicon.SetModelOutput(subject, name, data, exists)
python SimpleMidpoint.py Colin RKNE RANK MyMidpoint
要点 任一输入缺失时整帧标记为不存在，而不是只取有效的那一个点—— 这个“全有或全无”的策略在几何派生点里通常是对的。

DetectFootEvents.py

最完整的一个示例：遍历所有测力台，按合力阈值（默认 20 N）判断支撑相， 用“最近标记点落在台面范围内”来决定 Left / Right 上下文，最后创建 Foot Strike / Foot Off 事件。它还演示了如何处理 “设备采样率高于帧率”的采样索引换算。

关键步骤：

  1. 按 GetDeviceIDs 找设备，用 GetDeviceDetails()[1] == 'ForcePlate' 过滤。
  2. 用 GetDeviceOutputIDFromName(id, 'Force') + GetDeviceChannelIDFromName(..., 'Fx'/'Fy'/'Fz') 定位通道。
  3. 力用 GetDeviceChannelGlobal 读（全局坐标），CoP 用 GetDeviceChannel 读（局部，随后手算 /1000 转 m）。
  4. 每帧每采样算合力模长，越过阈值且 Fz < 0 视为着地。
  5. 用 ViconUtils.Globalise/Localise 把候选标记点变换到台面局部坐标，判断是否落在 LowerBounds…UpperBounds 内并取最近者定侧别。
  6. 写事件前先用 GetEvents 判重，避免重复标注。
vicon = ViconNexus.ViconNexus()
vicon.ClearAllEvents()
eventDetector = DetectFootEvents()
eventDetector.FindEvents(vicon, "Colin", 20.0, "LTOE", "LANK", "RTOE", "RANK")
照抄前先改三个地方
  • 受试者名与四个标记点名硬编码在 __main__ 里。
  • 索引混用：trajExists[idx] 里 idx 从 startFrame（1 基）开始，而列表是 0 基，实测会偏一帧。
  • SamplesPerFrame = deviceRate / rate 在 Python 2 里是整除、Python 3 里是浮点，后续 range 会炸。改用 int(...)。

GapFilling/ProcessGaps.py

只有 32 行：给定缺口两侧的帧号与轨迹数组，做线性插值，返回填补后的 (X, Y, Z, E)。它是纯函数，不碰 Nexus，方便单测。

def ProcessGaps(startGapFrame, endGapFrame, trajX, trajY, trajZ):
    dataX1, dataX2 = trajX[startGapFrame], trajX[endGapFrame]
    for frameNum in range(startGapFrame + 1, endGapFrame):
        x = dataX1 + (dataX2 - dataX1) * (frameNum - startGapFrame) \
            / (endGapFrame - startGapFrame)
        ...
    return (X, Y, Z, E)
两个细节 返回的 E 只在循环里赋值，若缺口长度为 0（起止相邻）会抛 UnboundLocalError；另外插值只在缺口内部做，端点缺失不处理。

GapFilling/FillGaps.py

批处理外壳：先扫 GetTrialRange() 区间内是否存在缺口，再统计每个缺口的长度， 只填补不超过 MaxGap 的，最后 SetTrajectory 写回。 

subjects = vicon.GetSubjectNames()
markers  = ['LTOE', 'RTOE']
FillGaps(vicon, subjects, markers, 4)      # 最多补 4 帧
  1. GetTrajectory 拿全量数据与存在性。
  2. 找到第一帧/最后一帧有效数据，界定处理区间（端点不插值）。
  3. 相邻有效帧号差 > 1 即一个缺口，记录 (前置帧, 后置帧) 与长度。
  4. 长度 ≤ MaxGap 的调用 ProcessGaps 填洞。
  5. SetTrajectory 一次性写回整条轨迹。
这是“最小可用”的补洞策略 线性插值只适合小缺口（≤4 帧）。大缺口建议先在 Nexus 里用 Woltring / Pattern fill， 或改用样条（SubmitSplineTrajectory）。

NexusConformityTest.py

给安装工程师用的验收脚本（v1.1, 2019-03-07）：对着标定杆（wand）采集的试次， 计算杆上两点间距的均值与标准差，判断系统精度是否满足出厂指标。

使用前提（脚本头部注释写明）：

  1. 新建 session，删除其中的受试者文件。
  2. 采集 ≥1000 帧、5 个标记点的标定杆试次（主动或被动）。
  3. 加载对应 VSK（如 …\CalibrationObjects\Active Wand v2.vsk）。
  4. Reconstruct + Label。
  5. 在 pipeline 中用 Run Python Operation 运行本脚本。

输出写进 Nexus Log，并额外生成两个文本文件与一份 CSV，供填入验收文档。

class Trajectory(object):
    def GetData(self, subject_name):
        self.x, self.y, self.z, self.occluded = v.GetTrajectory(subject_name, self.name)

def GetDistance(m1, m2, frame):
    return ((m1.x[frame]-m2.x[frame])**2 +
            (m1.y[frame]-m2.y[frame])**2 +
            (m1.z[frame]-m2.z[frame])**2) ** 0.5

它是一个“自包含脚本”，不是可复用库：模块级直接 v = ViconNexus.ViconNexus()， 导入即连接。作为 API 用法参考价值有限，但作为“如何写一个完整的批处理脚本”的样板不错。
