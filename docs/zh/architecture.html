架构与分层

理解 SDK 的四个层次，能解释绝大多数“为什么这个调用没反应 / 报这个错”的问题。

调用链

你的代码
  │  from viconnexusapi import ViconNexus

各层职责

层文件关注点
L1 门面 viconnexusapi/ViconNexus.py
ViconUtils.py		 类型转换、错误打印、NaN 语义处理、Python 2/3 字符串差异
L2 绑定 NexusClient3.py（~1856 行）
NexusClient.py（Py2）		 接口映射、Output_* 结果类型、容器类型；不要手改
L3 扩展 _NexusClient3.pyd 位数必须与 Python 解释器一致（x64）
L4 通信 ViconSDKClientCPP.dll
NexusSDKClientCPP.dll		 主机/端口、超时、命令序列化；版本兼容性在这一层决定

入口选择：Python 2 还是 3

ViconNexus.py 顶部按解释器版本选择底层模块，对使用者透明： 

if sys.version_info > (3, 0):
    from . import NexusClient3 as nexusclient     # 绑 _NexusClient3.pyd
    ...
else:
    from . import NexusClient as nexusclient      # 绑 _NexusClient.pyd
    ...

两个绑定暴露同一套方法名，所以业务代码不需要分支。但字符串在 Python 2 下是 str（bytes），因此门面层用 _get_safe_string_value() 统一 decode('utf-8')，你拿到的永远是 str。 反过来，所有入参在传给底层前都会 .encode('utf-8')。

返回值：Output_Result 家族

每个底层命令都返回一个 Output_* 对象，它们都继承自 Output_Result，因此都有：

成员说明
Error()bool，命令是否失败
ResultString()SafeString，失败原因文本

再各自附加数据成员，例如 Output_GetTrajectory 带 X/Y/Z/E，Output_GetSubjectNames 带 Names/Models/Active。 门面层正是把这些成员翻译成 Python 列表/元组返回给你的。

一次 GetTrajectory 的完整旅程

# 你的代码
x, y, z, e = vicon.GetTrajectory('Colin', 'C7')

# L1：编码字符串 → 调 L2 → 检查错误 → 展开 4 个 vector 为 list
def GetTrajectory(self, subject, marker):
    data = self.Client.GetTrajectory(subject.encode('utf-8'),
                                     marker.encode('utf-8'))
    if data.Error() and self.GenerateErrors:
        print(ViconNexus._get_safe_string_value(data.ResultString), file=sys.stderr)
    x, y, z, e = list(data.X), list(data.Y), list(data.Z), list(data.E)
    return x, y, z, e

# L2：SWIG 转发到 _NexusClient3
def GetTrajectory(self, i_rSubjectName, i_rMarkerName):
    return _NexusClient3.ViconNexusClient_GetTrajectory(
        self, i_rSubjectName, i_rMarkerName)
注意 失败时 data.X 等仍是空容器，方法会返回四个空列表而不是抛异常。 所以“读不到数据”通常表现为长度为 0，而不是报错。

打包方式

setup.py 读取同目录的 VERSION 文件作为版本号， find_packages() 收集包，include_package_data=True + MANIFEST.in 把 .pyd/.dll 一起带上。 这意味着：只要 wheel 是从这个目录构建的，二进制就跟着走， 使用者无需单独拷贝 DLL。

线程与并发

  • 客户端与 Nexus 之间是命令/响应模型，一次只能有一个命令在途。多线程并发调用需自行加锁。
  • RunPipeline / OpenTrial 等带 timeout 的方法，超时只是让客户端提前返回；宿主里的操作可能仍在继续。
  • 在 Nexus 内部脚本中执行长时间循环会阻塞 UI，建议外部进程驱动。
