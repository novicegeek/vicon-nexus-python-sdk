Example scripts

The SDK ships 8 examples covering the usual range of tasks, from "read the data out and have a look" to "batch gap filling and foot event detection". They are the quickest way into how the API is used, but they are all Python 2 syntax: to run them under Python 3 you have to change print and xrange.

How to run

Two modes, depending on whether the script calls OpenTrial / SaveTrial / RunPipeline:

:: Mode A: external process (recommended, full capabilities)
python DisplayTrialInfo.py

:: Mode B: inside Nexus — add a "Run Python Operation" to a Pipeline
:: fine as one step of a processing flow, but it cannot open or close trials

The examples' if __name__ == "__main__": block takes its arguments directly from sys.argv, so on the command line you have to supply whatever each script expects.

DisplayTrialInfo.py

The smallest "read something" example: trial name, path, frame count, frame rate, updatable range, subject list, device list.

(path, name) = vicon.GetTrialName()
framecount = vicon.GetFrameCount()
framerate  = vicon.GetFrameRate()
(startFrame, endFrame) = vicon.GetTrialRange()

for deviceID in vicon.GetDeviceIDs():
    deviceDetails = vicon.GetDeviceDetails(deviceID)
    deviceName, deviceType, deviceRate = deviceDetails[0:3]
    print 'Device', deviceID, deviceName, deviceType, deviceRate

It uses GetTrialName, GetFrameCount, GetTrialRange, GetDeviceIDs and GetDeviceDetails. Note that it has no Disconnect(); that is harmless for a one-shot script.

DisplaySubjectInfo.py

A subject profile: marker list → the markers associated with each bone segment → joint parent and child segments → static parameter values.

for Segment in vicon.GetSegmentNames(subject):
    markers = vicon.GetSegmentDetails(subject, Segment)[-1]
    print Segment, markers

for Joint in vicon.GetJointNames(subject):
    (parent, child) = vicon.GetJointDetails(subject, Joint)
    print Joint, '[', parent, '-', child, ']'

for param in vicon.GetSubjectParamNames(subject):
    value = vicon.GetSubjectParamDetails(subject, param)[0]
    unit  = vicon.GetSubjectParamDetails(subject, param)[1]

GetSegmentDetails(...)[-1] takes the third return value (markers). The parameter block calls GetSubjectParamDetails twice in a row, which is a redundant round trip — when writing your own, it is better to merge them into a single unpacking. 

python DisplaySubjectInfo.py Colin

SimpleMidpoint.py

Writes the midpoint of two markers into a new modeled marker. It demonstrates the whole "create output → read inputs → compute → write back" loop, and is the most common template for generating a custom point. 

vicon.CreateModeledMarker(subject, name)          # create the container first

(X1, Y1, Z1, E1) = vicon.GetTrajectory(subject, marker1)
(X2, Y2, Z2, E2) = vicon.GetTrajectory(subject, marker2)

(data, exists) = vicon.GetModelOutput(subject, name)
for i in range(vicon.GetFrameCount()):
    if E1[i] and E2[i]:
        exists[i] = True
        data[0][i] = (X1[i] + X2[i]) / 2.0
        data[1][i] = (Y1[i] + Y2[i]) / 2.0
        data[2][i] = (Z1[i] + Z2[i]) / 2.0
    else:
        exists[i] = False

vicon.SetModelOutput(subject, name, data, exists)
python SimpleMidpoint.py Colin RKNE RANK MyMidpoint
Key point If either input is missing the whole frame is marked as non-existent, rather than keeping only the point that is valid — this "all or nothing" policy is usually the right one for geometrically derived points.

DetectFootEvents.py

The most complete example: it iterates every force plate, decides stance from a total force threshold (20 N by default), uses "the nearest marker falls inside the plate bounds" to determine the Left / Right context, and finally creates Foot Strike / Foot Off events. It also shows how to convert sample indices when the device sample rate is higher than the frame rate.

Key steps:

  1. Find devices with GetDeviceIDs and filter on GetDeviceDetails()[1] == 'ForcePlate'.
  2. Locate channels with GetDeviceOutputIDFromName(id, 'Force') + GetDeviceChannelIDFromName(..., 'Fx'/'Fy'/'Fz').
  3. Forces are read with GetDeviceChannelGlobal (global coordinates), CoP with GetDeviceChannel (local, then divided by /1000 by hand to convert to m).
  4. Compute the total force magnitude for every sample of every frame; crossing the threshold together with Fz < 0 counts as foot contact.
  5. Use ViconUtils.Globalise/Localise to transform the candidate markers into plate-local coordinates, test whether they fall within LowerBounds…UpperBounds, and take the nearest one to decide the side.
  6. Check for duplicates with GetEvents before writing an event, to avoid labelling the same footfall twice.
vicon = ViconNexus.ViconNexus()
vicon.ClearAllEvents()
eventDetector = DetectFootEvents()
eventDetector.FindEvents(vicon, "Colin", 20.0, "LTOE", "LANK", "RTOE", "RANK")
Change three things before you copy it
  • The subject name and the four marker names are hard-coded in __main__.
  • Mixed indexing: in trajExists[idx] the idx starts at startFrame (1-based) while the list is 0-based, so in practice it is off by one frame.
  • SamplesPerFrame = deviceRate / rate is integer division in Python 2 but a float in Python 3, and the following range then blows up. Use int(...).

GapFilling/ProcessGaps.py

Only 32 lines: given the frame numbers on either side of a gap and the trajectory arrays, it interpolates linearly and returns the filled (X, Y, Z, E). It is a pure function that never touches Nexus, which makes it easy to unit test.

def ProcessGaps(startGapFrame, endGapFrame, trajX, trajY, trajZ):
    dataX1, dataX2 = trajX[startGapFrame], trajX[endGapFrame]
    for frameNum in range(startGapFrame + 1, endGapFrame):
        x = dataX1 + (dataX2 - dataX1) * (frameNum - startGapFrame) \
            / (endGapFrame - startGapFrame)
        ...
    return (X, Y, Z, E)
Two details The returned E is only assigned inside the loop, so a gap of length 0 (start and end adjacent) raises an UnboundLocalError; also, interpolation happens only inside the gap — missing endpoints are not handled.

GapFilling/FillGaps.py

The batch wrapper: first scan the GetTrialRange() interval for gaps, then measure the length of each gap, fill only those no longer than MaxGap, and finally write back with SetTrajectory. 

subjects = vicon.GetSubjectNames()
markers  = ['LTOE', 'RTOE']
FillGaps(vicon, subjects, markers, 4)      # fill at most 4 frames
  1. GetTrajectory fetches the full data and the existence flags.
  2. Find the first and the last frame with valid data to bound the processing interval (endpoints are not interpolated).
  3. A difference > 1 between adjacent valid frame numbers is a gap; record (frame before, frame after) and its length.
  4. Gaps with a length ≤ MaxGap are filled by calling ProcessGaps.
  5. SetTrajectory writes the whole trajectory back in one call.
This is the "minimum viable" gap-filling strategy Linear interpolation only suits small gaps (≤4 frames). For large gaps, prefer Woltring / Pattern fill inside Nexus first, or switch to a spline (SubmitSplineTrajectory).

NexusConformityTest.py

An acceptance script for installation engineers (v1.1, 2019-03-07): for a trial captured with a calibration wand, it computes the mean and standard deviation of the distance between the two points on the wand, to judge whether system accuracy meets the factory specification.

Prerequisites (as stated in the script header):

  1. Create a new session and delete the subject files in it.
  2. Capture a calibration wand trial (active or passive) with ≥1000 frames and 5 markers.
  3. Load the matching VSK (e.g. …\CalibrationObjects\Active Wand v2.vsk).
  4. Reconstruct + Label.
  5. Run this script from a pipeline with Run Python Operation.

The output goes to the Nexus Log, and it additionally produces two text files and one CSV to fill into the acceptance document.

class Trajectory(object):
    def GetData(self, subject_name):
        self.x, self.y, self.z, self.occluded = v.GetTrajectory(subject_name, self.name)

def GetDistance(m1, m2, frame):
    return ((m1.x[frame]-m2.x[frame])**2 +
            (m1.y[frame]-m2.y[frame])**2 +
            (m1.z[frame]-m2.z[frame])**2) ** 0.5

It is a self-contained script rather than a reusable library: at module level it does v = ViconNexus.ViconNexus() directly, so importing it connects. It has limited value as an API usage reference, but it is a decent template for how to write a complete batch script.
