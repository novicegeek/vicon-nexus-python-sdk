Low-level client

viconnexusapi.NexusClient3 (Python 3) and viconnexusapi.NexusClient (Python 2) are the binding layers generated by SWIG 4.0.2, mapping directly onto the C++ ViconNexusClient. Unless the facade layer is missing a feature, do not use them directly: they return Output_* objects, strings are SafeString, and lists are C++ containers.

Auto-generated, do not edit by hand The file header states “Do not make changes to this file unless you know what you are doing—modify the SWIG interface file instead”. Upgrading the SDK overwrites both files in their entirety.

ViconNexusClient

Its methods map one-to-one onto the facade layer methods of the same name (a few are exposed only at the low level). Every method returns an Output_* object, except for a handful such as IsConnected that return a raw bool. 

from viconnexusapi import NexusClient3

raw = NexusClient3.ViconNexusClient()
raw.Connect(b'localhost')
print(raw.IsConnected())

info = raw.GetServerInfo()            # Output_GetServerInfo
print(info.Error(), info.MajorVersion, info.MinorVersion)

raw.Disconnect()

Parameter naming Low-level formal parameters carry Hungarian prefixes: i_rSubjectName (input reference to a string), i_FrameNumber (input value), i_bForce (input bool). i_ = input, r = reference. The facade layer has already turned these names into readable ones.

General command channel

The Nexus command protocol is “a command name plus a parameter list”. These three methods expose the protocol itself, so you can call new commands supported by the host without shipping a new SDK version.

GetCommandList()Read

Enumerates every command name the host currently supports.

Returns Output_GetCommandList, whose CommandNames is a vectorss (vector of strings).

res = raw.GetCommandList()
for i in range(res.CommandNames.size()):
    print(res.CommandNames[i].Value())

GetCommandInfo(i_rCommandName)Read

Queries the signature of a single command: its parameter list and the type and name of each parameter.

Returns Output_GetCommandInfo, containing a sequence of Type_Parameter.

info = raw.GetCommandInfo(b'GetTrajectory')
print(info.Error(), info.ResultString().Value())

ProcessRequest(i_rCommandName, i_rInputParameters)Write

Executes an arbitrary command by name, with the parameters passed in as a list of Type_Parameter. Every facade method is essentially a specialisation of this one.

Returns Output_ProcessRequest.

What it is good for Probing the commands added by a newer Nexus version; or using a feature as an emergency stopgap while the facade layer has not wrapped it yet. Note that the parameters must be built in the order and with the types declared by GetCommandInfo.

# Building model output data by hand (what the facade does for you)
from viconnexusapi import NexusClient3 as nc

data = nc.map_ui_vd()
for component_index in range(3):
    values = nc.vectord()
    for frame in range(120):
        values.push_back(0.0)
    data[component_index] = values

exists = nc.vectorb()
for frame in range(120):
    exists.push_back(True)

raw.SetModelOutput(b'Colin', b'MyOutput', data, exists)
Why the facade needs AllocString The C++ interface's “string array” parameters want a vectorss whose elements must be SafeString rather than a Python str. That is why CreateModelOutput calls AllocString() on each one — see the call chain.

Python 2 differences

NexusClient.py is the Python 2 binding of the same interface (backed by _NexusClient.pyd), with identical method names. The differences are mainly in strings: under Python 2, str is just bytes, so the facade only applies encode('utf-8') to the AllocString input when sys.version_info < (3, 0).
